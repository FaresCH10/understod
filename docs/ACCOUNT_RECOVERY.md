# Account recovery checkpoint

S04/S06/A11 are partial, not production-ready. The default application remains local/synthetic. Recovery is implemented for credential-mode SQLite and the isolated synthetic PostgreSQL rehearsal; invitations, actual delivery and production integration remain open.

## Implemented contract

- Anonymous requests validate an exact email-only body and mutation origin. Eligible, unknown and throttled accounts receive the same accepted/queued response. The public handler does not look up credentials or return a token, delivery receipt or account status.
- Email and IP counters bound requests to five per 15-minute window. Redemption has separate token/IP counters. Global abuse budgets and counter retention still require implementation.
- The private worker looks up an active credential later. Unknown/disabled accounts are ignored without delivery. Tokens are random 32-byte secrets, stored only as hashes, expire 30 minutes after the request and are usable once.
- Recovery binds the canonical credential hash, selected site's role/monotonic access revision and linked account revision. Password rotation, account or site revocation/restoration and role changes invalidate earlier links. Redemption rechecks these values after asynchronous password derivation. If the original credential site's grant is disabled, another active linked grant can provide recovery authority without moving credentials.
- Password change, token consumption/revocation, all linked account-session revocations, changed-password notice and audit commit together. Recovery does not automatically sign in; other accounts and business evidence are not edited. See `STAFF_ACCOUNTS.md`.
- Mail payloads use AES-256-GCM with the job ID as authenticated context. Tokens and recipients are not stored as plaintext in the outbox. Terminal/expired jobs purge their private payloads.
- Delivery claims use leases, three bounded attempts and backoff. A retry retains the same encrypted link and provider idempotency key; stale completion cannot commit. External acknowledgement uncertainty is not exactly-once delivery proof.
- The browser keeps a reset token in memory and removes it from the visible URL. Reload of the sanitized URL shows an unavailable-link state rather than persisting credentials. A lost reset acknowledgement directs the user to try signing in before requesting another link; durable accepted-reset receipt recovery is not implemented.
- Local restore revokes unused recovery tokens and expires pending recovery mail. The synthetic PostgreSQL importer recognizes these local-only authentication tables but omits their secrets/delivery jobs, like credentials. Original backup/source rows remain intact; business and audit evidence still migrate.
- PostgreSQL migration 020 adds encrypted mail/token storage, scoped staff foreign keys and immutable token identity/consumption; 021 adds linked account identity/access guards and invalidates earlier-format unused links/mail. Requests serialize shared throttle counters. Reset now locks account before staff/credentials/tokens, matching account credential maintenance; private workers claim with `FOR UPDATE SKIP LOCKED` and fence completion by lease and expiry. Web/worker reuse the existing schema-scoped transactions. The importer also locks and requires empty target recovery tables.
- The PostgreSQL rehearsal exposes the same recovery/reset HTTP contracts with its separate cookie, and schedules expiry plus one awaited mail job per cycle. Email defaults to disabled, including in `.env.rehearsal.example`; no default production runtime or saved database cutover is enabled.

## Configuration and privacy

Email is disabled by default. `UNDERSTOOD_EMAIL_MODE=resend` requires protected server-side `UNDERSTOOD_RESEND_KEY`, normalized `UNDERSTOOD_EMAIL_FROM`, a private 32-byte hex `UNDERSTOOD_AUTH_MAIL_KEY` shared by web/worker, and exact `UNDERSTOOD_PUBLIC_ORIGIN`. Local HTTP origins require the explicit local allowance; otherwise the mail adapter requires HTTPS. Configuration alone does not verify provider/domain availability or delivery.

The adapter uses a fixed Resend endpoint, a ten-second timeout, no redirects, bounded responses and redacted errors. No live provider call has been executed. Before enabling it, authorize the account, verify the sending domain and current provider contract, approve privacy/residency, configure budgets and test actual delivery. Do not put keys in chat or source. Key rotation and terminal metadata retention are still open. Gemini free-tier policy is unchanged: synthetic data only, never real worker audio/responses.

## Remaining gates

Real-server concurrent reset/claim execution; production runtime integration; durable client acknowledgement recovery; invitation acceptance/reissue/revocation; operator quota/suspension enforcement; mail key rotation and metadata retention; production database grants, deployed delivery/privacy approval, reference fidelity and manual accessibility. PostgreSQL production restore must invalidate pending recovery state. The local/rehearsal implementation does not close these requirements.
