# Versioned Assessment Evaluation

Checkpoint: 2026-10-11. This is an engineering evaluation mechanism, not proof of
production language accuracy, comprehension or safe work.

Migration 067 extends scoped read-only observations to recorded assessments with
actual immutable transcription/assessment links and exact frozen input evidence.
The pipeline report separately shows one completed recorded case and three not
run, alongside the four typed cases. See AUDIO_PROVENANCE.md. No fabricated legacy
backfill or promotion of scripted results to model accuracy is performed.

The later isolated backend pipeline checkpoint adds a separately pinned schema-v2
dataset with frozen localized questions and normal credential/application paths.
See PIPELINE_REHEARSAL.md. The original dataset below remains unchanged; its broad
local semantic failures remain visible. Neither mocked command proves accuracy.

## Dataset And Provenance

`evaluation/assessment-v1.json` contains 43 synthetic samples: 34 labeled semantic
examples and nine mocked protocol-fault examples. Four frozen publication fixtures
cover shelf v3/v4 and carton v1/v2 question/rubric changes. EN/AR/UR answers include
paraphrases, a Lebanese Arabic dialect example, shelf swaps, negation, missing facts,
numbers/locations, ambiguity, unrelated answers and injection. Silence/noise are
text representations, not recorded audio. French is an unsupported-language probe.
Labels are engineering-authored, not independently reviewed native-language labels.

The catalog binds dataset version to canonical SHA-256:
`5dfd9aa385c803fa9e2bb91014216be158f46060a02957563bf581033fbeb065`.
Changing any sample, label, source, question or rubric requires a new version and
catalog entry; changing the content under the existing version is rejected.

Reports include dataset hash/version, sample/category/language, actual publication
ID/version, question/rubric/source/input hashes, model/adapter/prompt/schema
provenance, execution state, expected/actual outcome, bounded reason codes, result
and evidence hashes/counts. Raw answers, evidence quotes, credentials and database
connection strings are not report fields. Unknown reason strings are redacted.
Generated JSON reports use exclusive creation and never overwrite checkpoints.

## Commands

```powershell
npm run evaluate:contract
npm run evaluate:local
node scripts/evaluate-synthetic.mjs contract --output artifacts/new-contract-report.json
node scripts/evaluate-synthetic.mjs local --output artifacts/new-local-report.json
```

The default standalone command is now explicitly mocked contract evaluation.
It sends no network request, even if credentials are present. Mock responses are
constructed from engineering labels: a perfect semantic score here is tautological,
not evidence of inference quality. HTTP/rate-limit failures, uncertain transport,
malformed JSON, empty/blocked output, invalid reasons, invented quotes, missing
evidence and invalid fact indexes exercise the actual Gemini adapter and PostgreSQL
completion validator. Empty answers make zero mock requests; other samples make
one. There are 42 mock requests and zero external requests across the dataset.

Exit codes: 0 means the selected checks passed, 1 means semantic discrepancies,
incomplete semantic coverage or failed contract checks, and 2 means invalid
configuration/dataset/report output. Contract exit status is separate from its
injected-failure outcomes. Local mode intentionally exits 1 on the broader dataset.

The CI workflow runs the named contract command, not an accuracy gate. `npm test`
also retains the actual local checker comparison against all 19 legacy samples.
No failing broader-local evaluation has been disabled or relabeled as successful.
No fresh hosted CI run was performed at this checkpoint.

## Read-Only Runtime Evaluation

`scripts/evaluate-runtime.mjs` reads completed or pending typed assessments from an
explicit isolated synthetic PostgreSQL scope. It does not seed data, run a worker,
dispatch a provider request, change quota or mutate business/audit evidence.

Use the existing rehearsal environment and maintenance database credentials, with:

```text
UNDERSTOOD_TIER=local
UNDERSTOOD_DATA_CLASS=synthetic
UNDERSTOOD_POSTGRES_SCHEMA=understood_test_rehearsal
UNDERSTOOD_REHEARSAL_ORG_ID=<isolated synthetic organization>
UNDERSTOOD_REHEARSAL_SITE_ID=<isolated synthetic site>
UNDERSTOOD_EVALUATION_SYNTHETIC=true
```

Supply a JSON binding file; use actual accepted attempt IDs, never worker data:

```json
[{"sampleId":"cartons-correct","attemptId":"<actual synthetic attempt ID>"}]
```

```powershell
npm run evaluate:runtime -- bindings.json --output artifacts/new-runtime-report.json
```

Publication IDs may be generated by the real application. The reader compares the
stored source, version, language, exact effective question, private asked facts and
answer to the catalog fixture, then binds the report hash to the actual publication
ID. It cannot attach a stored answer to another version or question. Effective
questions in this dataset are English, including for multilingual answer samples;
a differently localized question needs its own new dataset version, not a relaxed
comparison. Later draft edits/withdrawal do not change the accepted historical input.

Tenant/site predicates and same-scope joins apply throughout. Duplicate sample or
attempt bindings, fault-sample bindings, arbitrary content, inconsistent versions,
invalid evidence and missing completion provenance are rejected. Completed Gemini
observations require the actual linked synthetic operation, matching input/model
provenance and one accepted request out of one reserved request. A transport HTTP
success alone is not a matching assessment. The reader uses a repeatable-read,
read-only transaction. This is a maintenance command, not a customer/operator API.

Queued/processing rows remain pending with no actual outcome. Failed/blocked jobs
remain unresolved, not fabricated completed "unassessable" assessments. Unmapped
samples remain `not_run`. A partial runtime report cannot produce a successful
semantic command exit. Stored provenance is not independent proof of live network
transport; a test can populate the same operation journal using a mock.

This checkpoint verifies the reader with disposable embedded PostgreSQL, actual
asynchronous assessment/quota processing and mocked Gemini transport. No external
PostgreSQL/provider, real worker content or saved main-preview writes were used.
Creating/dispatching a full authorized runtime evaluation is the next major task.

## Metrics And Acceptance

Reports retain overall confusion matrices plus per-language/category/model totals.
`semanticMetrics` excludes protocol-fault samples; `faultMetrics` reports them
separately. Every rate reports its denominator, and empty denominators are null:

- False matches: actual matched among completed expected nonmatches.
- False clarifications: actual clarification among completed expected matches.
- False unassessable: actual unassessable among completed expected matches.
- Unassessable total: genuine completed unassessable outcomes only.
- Failed/unresolved, not-run and all outcome disagreements are separate counts.

Failed/not-run samples do not disappear from the confusion matrix or count as
successful assessments. Fault frequency in this constructed set is not real-world
provider availability or language quality.

Every report keeps pilot acceptance `not_evaluated`, tolerances `awaiting_agreement`,
native-language QA `not_provided`, real-data permission false, hardware audio
untested and no semantic-accuracy claim. Independent labeling, dialect/audio/noise
coverage, actual authorized model runs and agreed low-risk pilot tolerances remain
launch gates. Gemini free tier remains synthetic-only.
