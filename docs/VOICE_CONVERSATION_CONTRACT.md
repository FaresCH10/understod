## Implemented

- Voice Help and reply HTTP receipts add captured clientContext without changing
  the domain receipt shape. Replies also bind the actual assignment ID supplied
  by the own-assignment history parent, not merely a case ID.
- Strict eight-field domain receipts and nine-field HTTP envelopes validate
  exact recording ID/digest, case, assignment, kind, canonical timestamps and
  storing/received/failed coherence. Private extras and context changes fail
  closed. A received receipt is not an answer assessment or AI match.
- Bounded credentialed/no-store requests use exact same-origin routes, GET-only
  receipt recovery and explicit WAV POST. The byte snapshot is copied and hashed
  again before dispatch; identity, selection and write authority are checked
  around hashing, transport and body parsing. No automatic upload retry.
- Metadata retention checks captured context/expiry/selection/authority before
  and after hashing and before storage. Existing namespace keys are retained
  so previously uncertain commands are not hidden by a key-format migration.
  Storage holds only UUID/digest, never WAV bytes or plaintext.
- The keyed recorder accepts live own-session callbacks, aborts owned requests
  on cleanup and maps failures to localized EN/AR/UR notices. Unknown storage
  and missing receipts never become successful delivery or confirmed absence.
- An uncertain upload's local preview can be discarded with confirmation,
  preserving its metadata and GET receipt recovery. This neither cancels a
  request nor deletes server audio. A new recording is not substituted for
  the pending original ID/digest. Cancel-first focus trapping and scope/intent
  guards are implemented; full rendered discard acceptance remains untested.
