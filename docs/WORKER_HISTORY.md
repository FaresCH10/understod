# Worker Receipts And History

The default SQLite browser and isolated PostgreSQL HTTP rehearsal share worker-visible `assessmentStatus`, `dueAt`, publication state and explicit content fields. A pending typed answer is received, not an unsubmitted task or a completed assessment. Failed recordings retain received status but permit retry on an open assignment. Outcomes do not certify understanding.

Worker inbox tabs are To do, Sent answers and History, localized in EN/AR/UR. Both `/api/worker/briefings` and `/api/worker/history` now return paged objects, not the former capped arrays. Earlier assignment details remain readable, while new answers/help are denied by the server. Deadline state is captured on detail load so a clock tick does not discard an unsent recording; the server always rechecks actual acceptance.

Help history reads the existing scoped worker DTO: original independently stored help text, open/resolved status, timestamp and owner name only. Assessment follow-up uses a neutral label when there is no independent help text. Private reasons, supervisor notes, rubric and storage references are excluded. Refresh is read-only; successful help submission refreshes the saved history. Input minimum and in-flight controls agree with the server. This is not a translated conversation or supervisor message delivery system.
