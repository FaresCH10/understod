# Staff invitations

Backend/client checkpoint: 2026-10-06. Partial implementation, not production-ready onboarding.

## Implemented

- SQLite and PostgreSQL migration 022 store site-scoped invitations, generation-bound hashed links, encrypted recipients/mail, immutable mutation and acceptance receipts.
- Owner may invite site roles; administrator may invite supervisors/auditors only. Active credential identity, current site role/access revision and account access revision are rechecked. Disable/restore does not reactivate earlier links.
- Issue and resend return queued, never sent. No token is generated on issue. The awaited worker creates the encrypted one-use fragment link before calling the fixed mail adapter. Expiry is 48 hours; each generation has at most three delivery attempts and a 30-second lease. Retry retains the exact encrypted message and provider idempotency key.
- Resend revokes earlier generations and pending mail. Cancellation closes the invitation permanently. Expired invitations need an explicit new issue, not resend. Provider acknowledgement cannot undo cancellation or stale authority; it is not proof of inbox delivery.
- Signup consumes the current link and creates a credential account/site membership atomically with receipt and audit. Existing accounts must sign in with the matching recipient email; acceptance adds a new site grant without replacing a password, changing existing roles or switching the session. Signup does not automatically sign in.
- Exact acceptance retry requires the original request ID and recipient proof. Competing same-request signup creates one account/membership; a PostgreSQL replay discovered after locking releases and reacquires ordered account locks. Different request reuse fails. Public preview/accept share token/IP limits of ten per 15-minute window.
- Private list/receipt reads are role/site bounded, paginated and masked. Expired list status is derived without a write. SQL/provider/encryption errors are redacted at HTTP boundaries. Real session revocation is checked again inside invitation operations.
- Native restore revokes outstanding links, expires pending invitations and purges pending payloads while keeping accepted receipts. Synthetic PostgreSQL cutover preserves invitation history/account links and revokes token hashes, expires pending invitations and removes all mail/recipient ciphertext. Credentials are still omitted; no local mail is replayed.
- Credential settings provide masked bounded invitation pages, role-limited issue/resend/cancel dialogs and explicit consent. Tab-local actor/site recovery persists the original request before posting, verifies exact normalized receipts through GET and permits an unchanged retry only when no accepted receipt is found. Invalid acknowledgements never clear pending evidence.
- Acceptance sanitizes the bearer fragment immediately and keeps the raw token/password only in component memory. Tab-local acceptance recovery is keyed by the token digest and contains only request ID, account kind and masked preview. Reopening the original email link can resume the same request with recipient proof; a sanitized-page reload cannot reconstruct the bearer token. Signup never auto-signs in; existing acceptance leaves the selected site unchanged until an explicit site-selection command.

## Routes

Credential-only anonymous POST: `/api/auth/invitations/preview`, `/api/auth/invitations/signup`; signed-in recipient POST: `/api/auth/invitations/accept`. Tokens are JSON-body only, never query/path values. Mutations require the configured origin. Public results contain no raw recipient email or bearer token.

Staff GET/POST: `/api/settings/invitations`; GET `/api/settings/invitations/receipts/:requestId`; confirmed POST `/api/settings/invitations/:id/resend` and `/cancel`. No caller-selected tenant/site is accepted.
