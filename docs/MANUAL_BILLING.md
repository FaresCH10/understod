# Manual Billing

2026-10-05 checkpoint, S35 partial. Application ledger only, not payment processing or bank reconciliation.

SQLite and PostgreSQL implement immutable issued invoices and received payments, exact positive USD cents up to 1,000,000,000, frozen issuer/site labels, due dates, partial/paid/outstanding totals, private bounded lists/details and escaped printable HTML downloads. Active scoped owners mutate after explicit confirmation; auditors read only. Other roles/inactive/foreign principals are denied by authoritative database checks. Workers receive no billing content.

Stable UUID requests replay normalized identical payloads without another entry/audit. Changed payloads conflict. Replay precedes remaining-balance checks, including after settlement. Payment insertion guards overpayment; audit failure rolls back records. PostgreSQL request/invoice locks serialize application writes; embedded tests do not prove real-server concurrency. Migrations 013/014 and the synthetic backup importer preserve records, labels and replay receipts.

Owners can explicitly void an unpaid invoice after confirming its frozen number/amount and entering a reason. A separate immutable `invoice_voids` receipt retains the reason/time; original issued evidence is not edited. Original total, paid amount, voided amount and outstanding balance stay distinct; a voided invoice is never shown as paid. Application and database insertion guards deny payments on voids and voids on any received payment. PostgreSQL both actions lock the parent invoice. Paid/partially paid corrections are not refunds and remain unimplemented. Void receipt lookup and unchanged retries use the same scoped tab-local recovery as invoice/payment saves.

The `settings/invoices` UI has search/status/page, creation, preview, payment paging, confirmation and download. Edits clear confirmation. A synchronous in-flight guard/locked unchanged retry handles lost acknowledgments. Refresh/back within billing are disabled during uncertainty. A bounded pending request is retained in sessionStorage, keyed by owner/org/site; sign-out clears it. Pending amount/reference/description/date are private tab-local data, not encrypted device storage. On reload/navigation, an authenticated owner-only receipt lookup first reconciles an accepted request without writing again; an absent receipt offers explicit unchanged retry, never automatic resubmission or a second UUID. Unavailable/corrupt tab storage fails closed. Other identities/sites cannot read another principal's recovery receipt. Downloads are private no-store/nosniff/restrictive-CSP HTML, not a tax-compliance/PDF claim.
